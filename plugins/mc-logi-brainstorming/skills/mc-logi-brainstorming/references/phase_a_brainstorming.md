# Phase A — 경량 브레인스토밍 원칙

## superpowers:brainstorming 에서 차용하는 원칙
- 컨텍스트 선탐색 후 질문 (파일/기존 ITEM 정찰)
- **한 번에 하나씩** 질문 (여러 질문으로 압도 금지)
- 객관식(AskUserQuestion) 우선, 개방형은 필요 시
- 2~3개 접근법을 트레이드오프와 함께 제안, 추천안을 먼저
- 큰 범위면 먼저 분해 제안 (독립 서브흐름 분리)

## ★ 차용하지 않는 것 (HARD-GATE 미상속)
- superpowers:brainstorming 의 "종착점 = writing-plans" 강제를 **상속하지 않는다**.
- 본 스킬의 종착점은 Phase D(산출물 책정)다. writing-plans / 구현 계획으로 가지 않는다.
- 설계 문서(docs/superpowers/specs)도 작성하지 않는다 — 산출은 scene-sketch + 책정 리포트.

## 질문 전략
- purpose: 무엇을 위한 시나리오인가
- 제약: 기존 시스템·도메인·외부 연동 제약
- 성공기준: 이 시나리오가 다루면 "끝"인 경계
- actor·트리거·결정포인트(hotspot)를 끌어내는 질문 우선

## 접근법 제안 패턴
- 시나리오를 풀어가는 2~3가지 흐름안 제시 (예: 동기 vs 비동기, 자동 vs 수동 승인)
- 각 안의 산출물 영향(어떤 ERD/API가 더 필요한지)을 가볍게 언급 → Phase D 예열
