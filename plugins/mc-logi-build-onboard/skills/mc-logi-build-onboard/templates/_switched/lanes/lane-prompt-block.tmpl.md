## 레인 규칙 (병행 레인 · 표준 블록)

**자리**
- 너는 작업 레인 `<레인>` 이다. 워크트리 `<메인>/.claude/worktrees/lane-<이름>` (브랜치 `lane/<이름>`) **안에서만** 일한다.
- 메인 폴더 `<메인>` 의 파일은 **읽기만** 한다 — 고치지도 커밋하지도 마라. 경로는 늘 워크트리 절대경로로 쓴다.
- 🚫 새 작업 공간이 필요해도 워크트리 폴더를 `cp` 로 복사하지 마라 — 필요하면 멈추고 보고한다(새 공간은 오케스트레이터가 `git worktree add`/Orca 로 만든다).
- 환경은 준비돼 있다(`scripts/lanes/lane-prep.sh`). 다시 설치하지 마라.

**진실원**
- 이 지시는 진실원이 아니다. 변경지시서 `<워크트리>/{{change_orders_path}}CO-NNN-*.md` §3 과 코드·설계를 **조회로 확인**하고, 다르면 바로잡아 하고 보고에 적어라.
- 키트(`docs/design/**` 등 내려받은 설계 파일)·생성물을 고쳐야 할 것 같으면 **고치지 말고 멈춰서 보고**한다(키트는 read-only).

**노하우**
- 착수 전에 에이전트 본체의 `## 노하우 색인` 을 **모든 행** 훑고, 해당 묶음을 실제로 열어 읽어라(머리말 먼저).
  `knowhow_dir_abs: <워크트리>/{{knowhow_dir}}`
- 작업 도중 색인의 «이 행동»을 하려는 순간 그 행을 다시 봐라. 출력 `knowhow_read` 는 **필수**다(읽은 묶음 + 해당 없다고 본 행 전부).

**검사 — 순서와 판정**
- 바꾼 갈래만 이 저장소의 검사 명령(lint·typecheck·build)으로 돌리고, 시험은 **연관 시험 + 항상 묶음**만 돌린다:

{{test_scope_table}}

- ★ **레인에서는 전체 시험을 돌리지 않는다** — 바꾼 파일과 그 직접 사용처의 시험만 골라 돌린다. 전체 시험은 합치기(`lane-merge.sh`)가 최신 메인 위에서 한 번 돈다(작업자 · QA · 합치기가 같은 전체 시험을 세 번 돌리면 레인 둘만 겹쳐도 CPU 가 찬다 · 실측).
<!-- IF lane_heavy_tests -->
- 🚫 **무거운 시험은 레인에서 돌리지 마라** — {{lane_heavy_tests}}. 공유 자원(DB 등)을 레인들이 함께 써서 **한 번에 한 레인만** 돈다(오케스트레이터가 합칠 때 정한다). 레인에서는 바꾼 부분의 시험만 골라 돌린다.
<!-- ENDIF lane_heavy_tests -->
- 판정: 종료코드를 `| tail` 같은 파이프로 가리지 마라 — 출력은 파일로 받고 종료코드를 따로 본다. 시험은 **통과 건수 줄이 실제로 있어야** 초록이다(빈 실행 = 초록 아님).
- 출력·보고에서 자격증명이 실린 주소(`scheme://user:pass@…`)를 거른다 — 시험 하네스 오류 문구가 DB 비밀번호를 찍은 적이 있다.

**금지**
- 설정·환경 파일(`~/.claude.json` · `.env` · 키 파일)을 `cat`/출력하지 마라. 키는 환경 변수로만 넘기고 값을 찍지 마라.
- 개발 서버를 직접 띄우지 마라. 레인 포트에는 로그인 세션이 없다 — 화면 확인은 **합친 뒤 메인에서** 한다.
- 🚫 **운영 데이터·운영 서버를 건드리지 마라** — 읽기 위한 접속도 지시에 명시된 경우만.
- 레인용 로컬 서비스(DB·컨테이너)를 멈추거나 지우지 마라 — 필요하면 멈추고 보고한다(사용자 동의 사항).
- 🚫 **일부러 CPU 부하를 만들지 마라** — `yes > /dev/null` · 같은 시험을 여러 개 동시에 띄우기 · 부하용 반복문 금지. 흔들리는 시험은 **순차로**(한 번에 하나) 반복하고, 가짜 시계·주입한 시각으로 원인을 고친다. (실측: 작업자가 부하용 프로세스 10개를 띄워 놓고 끝내지 않아 레인을 지운 뒤에도 하루 가까이 코어를 썼다.)
- 🚫 백그라운드로 띄운 프로세스(`&` · nohup · 감시 모드 시험)는 **보고하기 전에 전부 끝낸다** — 끝내기 직전에 `pgrep -l <이름>` 으로 내가 띄운 것이 남았는지 본다. 🚫 `pgrep -f`·`-fl`·`ps` 의 명령줄 출력은 쓰지 마라 — 다른 프로세스 명령줄의 비밀 값(토큰 등)이 출력에 실린다(실측).
- `git stash` · `git checkout --` · `git restore` · `git add -A` 금지.
- **공용 기록을 쓰지 마라**: `{{change_orders_path}}MASTER.md` · CO 의 상태·로그 줄 · `{{knowhow_dir}}` · LogiCraft(work_claim · IMPREC · 설계 반영). 남길 것은 보고 `learned` 에 적어라.
  (예외 하나: **백필 레인**은 MASTER 의 «설계반영» 칸과 LogiCraft 설계 반영이 본업이다 — 지시가 백필 레인이라고 적은 경우만. 구현·배포 칸은 백필 레인도 쓰지 않는다.)
- **보고·출력 서술은 사용자의 언어로 쓴다**(이 프로젝트 지침이 정한 언어 · 없으면 사용자가 쓰는 언어). 코드·식별자·명령·경로는 원형 그대로.
- **번호를 새로 잡지 마라**(CO 번호 · 마이그레이션 번호 등) — 지시에 적힌 번호만 쓴다. 필요하면 멈추고 보고한다(같은 시기 레인들이 같은 번호를 쓴 사고가 있었다).

**커밋**
- 바꾼 파일만 경로를 적어 `git add <경로…>` · CO 하나에 커밋 하나 · 메시지 첫 줄 `CO-NNN <요지>`. 푸시하지 마라(합치기는 오케스트레이터).
- ☠️ **QA 가 도는 동안에는 레인에 아무것도 쓰지 마라**(커밋·파일 수정 모두) — QA 는 레인 커밋 하나에 고정돼 있다. 바뀌면 그 판정은 무효가 된다.

--- Orca 복사 시작

## Orca 작업자 (lane-orca.sh 로 띄운 레인)

**★ 첫 단계 — 자리 확인과 준비**
- 너의 워크트리는 **Orca 가 만든 이 세션의 폴더**다. 위 블록의 `<워크트리>` 는 그 경로다 — 먼저
  `git rev-parse --show-toplevel` 과 `git branch --show-current` 로 경로·브랜치를 확인하고 보고에 적어라.
- 그다음 **`scripts/lanes/lane-prep.sh`** 를 그 폴더에서 포그라운드로 돌린다(몇 분 걸릴 수 있다 · timeout 600000).
  종료코드 0 과 「✅ 레인 준비 끝」이 나와야 다음으로 간다. 실패하면 고치려 들지 말고 `escalation` 으로 알린다.

**차례 — 백그라운드로 끝내지 마라**
- 🚫 `run_in_background` · 백그라운드 대기(`&` · 감시를 걸고 차례 끝내기)로 차례를 끝내지 마라 —
  Orca 는 차례가 끝나면 멈춘 것으로 본다(실측: 시험을 백그라운드로 걸고 끝낸 작업자가 「멈춤」 처리돼 손으로 깨웠다).
  긴 명령도 포그라운드로 기다리고 timeout 을 넉넉히(최대 600000ms) 준다.
- 끝은 반드시 **`worker_done` 한 번**이다(못 끝냈으면 `--outcome failed`). 물을 것은 `orca orchestration ask` —
  로컬 질문 창은 코디네이터가 못 본다.

**역할 — 구현은 도메인 에이전트, 작업자는 검사·커밋·보고**
- Orca 작업자는 도메인 에이전트 정의(도구 제한 · 내장 진실원·함정 · 노하우 색인)를 그대로 받지 못한다.
  그래서 **이 지시가 서브에이전트를 요청한다** — 이 세션 안에서 해당 도메인 에이전트를 서브에이전트로 띄워
  (Agent 도구 · subagent_type `<매핑표의 도메인 에이전트명>`<!-- IF frontend_track --> / `{{prefix}}-web-implementer`<!-- ENDIF frontend_track -->) 구현시킨다.
  프롬프트는 위 「도메인 에이전트를 직접 띄울 때」 꼴 그대로 + 위 「레인 규칙」 블록(`<워크트리>` 는 확인한 경로로 채운다).
- 작업자 자신은: 에이전트 결과 회수 → 위 「검사」를 **실측으로 다시** 돌림(에이전트 보고를 믿지 않는다) → 커밋 →
  보고 YAML 을 `worker_done` 본문에.
- 도메인 에이전트가 없는 일(개발 도구·문서만 바꾸는 CO)은 작업자가 직접 한다 — 지시에 그렇게 적혀 있을 때만.
- 띄우는 서브에이전트는 CO 가 정한 도메인 에이전트뿐이다 — 그 밖의 도우미·작업자는 띄우지 마라.
