# mc-logi-build-onboard — 구현 오케스트레이션 세트 온보딩

현재 프로젝트에 맞는 **구현 오케스트레이션 세트**(수정 dispatch · 설계 backfill · (greenfield 시) build · (앱 표면 있으면) E2E 3종 + 도메인별 implementer · 독립 QA 에이전트)를 조립해 방출하는 **메타 스킬**이다.

## 왜 필요한가

프로젝트마다 dispatch/build/backfill 스킬과 도메인 에이전트를 손으로 포팅하면 **매번 미묘하게 달라진다**. 어떤 프로젝트엔 work_claim 이 빠지고, 어떤 프로젝트엔 커밋 절차가 옛 버전이고, 도메인 에이전트의 경계 문구가 제각각이 된다. 그 드리프트는 **문제가 터지고 나서야** 보인다.

이 스킬은 세트를 **불변 뼈대 + 스위치 조각 + 슬롯** 3층으로 분해해, 프로젝트 구조를 판정한 뒤 결정적으로 조립한다. 같은 구조면 같은 세트가 나온다.

| 층 | 뜻 | 처리 |
|---|---|---|
| 🟩 불변 | 어느 프로젝트든 거의 동일 | 항상 삽입 |
| 🟨 스위치 | 뼈대 자체를 켜고 끔 (13개) | Discovery + 인터뷰로 판정 |
| 🟥 슬롯 | 값만 채움 | 치환 |

## 13개 스위치

**구조축** — `has_build`(빌더 생성 여부, "2종 vs 3종"을 가름) · `phase0_foundation`(공통기반 선순차) · `dependency_layers`(계약 의존 순서) · `work_claim`(멀티세션 점유) · `commit_strategy` · `agent_mode` · `conventions_location` · `code_boundary`

**E2E축** — `e2e_track`(마스터) · `e2e_design_link` · `e2e_auth` · `e2e_selector` · `e2e_account_strategy`

각 스위치는 **① 무엇을 제어하나 ② 자동 판정 신호 ③ 값 ④ 게이트하는 조각 ⑤ 왜 중요한가**를 갖는다. 판정이 애매하면 추정하지 않고 인터뷰한다.

## 이 스킬이 막는 두 가지 검증 공백

**로그인은 두 역할을 겸한다** (`e2e_auth`) — 다른 걸 검증하려고 들어가는 *전제조건*이면 우회가 옳다. 그러나 로그인 자체가 요구사항이면 우회한 순간 **한 번도 검증되지 않은 채 모든 시나리오가 초록**이 된다. 그래서 `none` / `bypass` / `bypass_and_verify` 로 강제 분리한다.

**계정 조달을 안 정하면 두 개가 동시에 터진다** (`e2e_account_strategy`) — ① 권한이 필요한 시나리오가 403 으로 막혀 "미커버"로 조용히 빠지고, ② 급한 대로 시드 계정 비밀번호가 spec 에 하드코딩돼 **저장소에 커밋**된다.

## 아키타입 프리셋

| | `greenfield-monolith` | `brownfield-submodule` |
|---|---|---|
| has_build | on (build 포함 3종) | off (dispatch·backfill 2종) |
| 진실원 | 설계 키트 | 변경지시서(CO) |
| conventions | shared | embedded |
| 경계 | package | submodule |

프리셋 밖 구조(brownfield-monolith, greenfield-multirepo 등)는 **통짜 아키타입을 새로 만들지 않고** 스위치를 의존 순서대로 개별 판정해 조합한다. 오버라이드한 스위치는 게이트에서 ⚠️ 로 표시해 검토받는다.

## 파이프라인 (게이트 4개)

```
Phase 0  Discovery      repo 스캔 + 설계 조회 + E2E 실측
Phase 1  스위치 확정    🚦 근거·override 표시한 표로 확인
Phase 2  슬롯 인터뷰    🚦 prefix · work_claim · 계층 · 계정 전략
Phase 3  조립           결정적 치환 (외부 엔진 없음)
Phase 4  도메인 지침    🚦 설계 정독 → 근거 ID 붙여 초안
Phase 5  검증·완료      🚦 미치환 마커 · 에이전트 교차검증 · 부트스트랩 생성
```

**E2E 슬롯은 추정하지 않고 돌려보고 채운다** — 앱을 실제로 띄우고, 인증 우회를 태워보고, 삭제 API 를 호출해보고, 권한을 실제로 써본다. 문서와 다른 기동 명령이나 400·403 응답으로만 드러나는 제약이 거기서 나온다.

## 재온보딩

이미 세트가 있는 프로젝트에서 다시 실행하면 기존 파일과 새 조립 결과를 **diff** 로 보여주고, 스위치 변경(예: 팀 합류 → work_claim on)만 반영한다. 도메인 지침에 축적된 **노하우는 보존**한다.

## 원칙

AI 임의 추정 금지 — 스위치·슬롯 값은 repo/설계 근거 또는 인터뷰로만 확정한다. 근거가 없으면 비우고 "정보부족"으로 보고한다(placeholder·가짜 ID 금지). 이 스킬은 세트를 **방출만** 하고 구현을 돌리지 않는다.
