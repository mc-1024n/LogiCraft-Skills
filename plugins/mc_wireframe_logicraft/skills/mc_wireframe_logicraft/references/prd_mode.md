# 모드 B — PRD + IA 차트 기반 와이어프레임 워크플로우

기획서(PRD)와 IA(Information Architecture) 차트를 받아 일반 패턴 와이어프레임을 생성한다. wireframe_basic 의 학습 패턴 라이브러리를 그대로 활용.

## 필수 입력 자료

### 1) 기획서 (PRD)
- 제품/기능 명세서, 화면 설명 문서
- 각 화면의 목적, 주요 액션, 표시 정보
- 사용자 플로우 (선택)

### 2) IA 차트
- 사이트맵 또는 화면 구조도
- 화면 간 이동 경로
- 계층 구조 (Depth 1/2/3)

**두 자료가 모두 제공되지 않으면 진행 불가** → 재요청.

---

## 실행 흐름

1. 가이드 안내 → 사용자에게 모드 B 설명 + 자료 요청 (SKILL.md 의 시작 안내 활용)
2. 자료 수집 → PRD + IA 차트 수신·파싱 (텍스트, 첨부파일, 이미지 등)
3. 화면 리스트 도출 → IA 기반으로 그릴 화면 목록 확정 → **사용자 확인**
4. Figma 파일 확인 → `get_metadata`, `get_screenshot` 으로 기존 상태 파악
5. 와이어프레임 생성 → `use_figma` 로 섹션별 분할 호출하여 프레임 생성
6. 결과 검증 → `get_screenshot` 으로 결과 공유

### 화면 리스트 확정 (3단계 상세)

IA 차트에서 추출한 화면 목록을 사용자에게 보여주고 확인받는다:

```
IA 분석 결과 다음 화면들을 확인했습니다:

  Depth 1:
    - 메인 (Home)
    - 로그인 / 회원가입

  Depth 2:
    - 마이페이지
    - 결제 내역

  Depth 3:
    - 주문 상세
    - 결제 진행

위 화면 모두 그릴까요? 또는 일부만 선택하시겠어요?
```

사용자 응답 후 진행.

## 학습된 패턴 라이브러리

본 스킬이 생성 가능한 컴포넌트·섹션 패턴 범위. 이 범위를 벗어나는 화면은 단순화될 수 있음.

### 레이아웃 기본
- Desktop 너비: **1440px**
- Content 좌우 패딩: **100px**
- 섹션 간 수직 간격: **80~100px**

### 헤더 (Header)
- 로고(좌) + 네비게이션(중앙) + CTA 버튼(우)
- 높이: 64~80px
- 배경 `#FFFFFF`, 하단 1px `#D1D1D1` 보더

### 히어로 (Hero)
- 좌측 타이틀 + 우측 이미지/카드 2단 구성
- 또는 중앙 정렬 타이틀 + 서브카피 + CTA
- 높이: 480~600px

### 피처 카드 그리드
- 3열 또는 4열 카드
- 카드 = 상단 이미지 플레이스홀더 + 카테고리 태그 + 제목 + 설명
- 카드 padding 24, 간격 24

### Stats 섹션
- 큰 숫자 + 라벨 (2~4개 가로 배치)
- Stat 컴포넌트: Bold 32~40px 숫자 + Regular 14px 라벨

### CTA 섹션
- 타이틀 + 서브카피 + Primary 버튼(다크 필)
- 중앙 정렬, 좌우 여백 충분히

### 푸터 (Footer)
- 회사정보 + 링크 3~4열 + 저작권
- 배경 `#1A1A1A` (다크), 텍스트 `#FFFFFF` 또는 `#999999`
- 또는 `#F5F5F5` (라이트), 텍스트 `#333333`

### 추가 컴포넌트
- Step 인디케이터 (01, 02, 03)
- 도트 페이지네이션 (캐러셀)
- 태그/배지 (라운드 필)
- 테이블 / 리스트
- 폼 (라벨+입력+버튼)
- 모달 다이얼로그

### 적용 가이드
- 기획서·IA 에서 화면 종류·목적 파악 후 위 패턴들 조합
- 컬러·폰트·오토레이아웃 규칙은 `references/grayscale_rules.md` 참조 (필수)
- Figma JS 코드 패턴·헬퍼 함수는 `references/figma_helpers.md` 참조

### 패턴에 없는 요소
- 어드민 대시보드, 복잡한 폼, 데이터 차트 시각화 등은 단순화 또는 회색 박스 + 라벨로 표현
- 도메인 특화 위젯 (지도·차트·동영상 플레이어 등) → 회색 박스 + 라벨로 placeholder

## 에러 처리

### 자료 부족
- PRD 만 있고 IA 없음 → "IA 차트가 필요합니다. 화면 구조도나 사이트맵을 함께 제공해 주세요."
- IA 만 있고 PRD 없음 → "각 화면의 목적·기능 설명이 필요합니다. 기획서 또는 텍스트 설명을 제공해 주세요."
- 둘 다 부실 → 자세한 자료 재요청

### Figma MCP 부재
"Figma MCP 도구를 사용할 수 없습니다. Figma 데스크톱 앱에서 Plugin → Claude MCP 연결을 먼저 확인해 주세요." 보고 후 중단.

### 화면 너무 많음
사용자가 한 번에 10개 이상 화면 요청 시:
- 우선 3~5개만 그리고 사용자 검토 받기 권장
- "한 번에 너무 많은 화면을 생성하면 노드 수 제한·검토 부담이 큽니다. 우선 핵심 화면 N개 부터 그리고 나머지는 다음 단계로 진행할까요?"

## 한계

- 기획서·IA 가 모호하면 결과도 모호함 (garbage in, garbage out)
- 컬러 시안·인터랙션·애니메이션은 표현 불가 (정적 와이어프레임)
- 복잡한 어드민 화면은 단순화됨
- 모드 A (Logicraft 기반) 가 더 정확한 결과 → 가능하면 SCREEN 정의 후 모드 A 사용 권장
