# 경위 판정 지침 — 본문에서 분리할 경위 가르기

## 무엇을 하나

설계 도구 LogiCraft 의 항목 본문(description·notes·rationale 등)에는 **현행 정의·규칙·이유**와
**경위**(무엇이 언제 왜 바뀌었나 · 정정 이력 · 검증 기록)가 섞여 있다. 경위를 본문에서 **분리**하려 한다.
분리한 경위는 사라지지 않는다 — 원문은 적용 직전 버전(항목 버전 이력)에 그대로 있고 변경 요약이 그 버전을 가리킨다.

네 일은 문단마다 아래 네 부류 중 하나를 정하는 것이다. 원문은 버전에 남지만,
현행 규칙을 잘못 옮기면 본문에서 규칙이 빠진다 — 확신 없으면 `현행` 으로 두라(본문에 남는 게 안전하다).

## 부류

| kind | 뜻 | move |
|---|---|---|
| `경위` | 문단 전체가 경위 — 지금 규칙을 읽는 데 없어도 된다 | 비워 두면 문단 전체를 옮긴다 |
| `혼합` | 현행 문장과 경위 문장이 섞였다 | **옮길 조각만** 원문 그대로(복사·붙여넣기 수준으로 정확히). 여러 개 가능 |
| `현행` | 지금 유효한 정의·규칙·이유 — 본문에 있어야 한다 | 없음 |
| `본문 충돌` | 정정·변경 기록이 **본문의 옛 서술을 뒤집었는데 본문은 그대로** — 경위만 빼면 틀린 규칙이 남는다 | 없음(담당자가 본문부터 고친다) |

`경위`·`혼합`·`본문 충돌` 은 `reason` 필수(한 줄, 핵심 구절 인용).

## 경위의 모양 (옮긴다)

- 날짜 붙은 변경 기록: 「2026-09-15 ADR-149 — 탭 경계 → 상태 필터 경계로 정정 …」
- 검증·증적 기록: 「CO-147 e2e (fd6850d) — API 축 통과 · 화면 축 조건부 skip …」, 「증적 void」, 「blocked 유지」
- 세션·결정 로그: 「Session 93 R7~R8 (2026-05-27): …」, 「D23/D24 …」
- 해소·철회 기록: 「종전의 … 표기는 해소됐다」, 「예고는 해소됐다」, 「더 이상 남은 사유가 아니다」, 「이번 변경은 … 범위 축소다」
  (☠️ 날짜·CO 번호가 **없어도** 경위일 수 있다)
- 커밋·배포 기록: 「(web 커밋, 2026-08-31 통합)」

## 경위가 아닌 것 (남긴다 — `현행`)

- ☠️ **버전·출처 표기가 붙은 현행 규칙**: 「(ADR-028 v3)」, 「명세서 v1.1 §4.6 직역」, 「(★ CO-016 핵심)」,
  「(Session 93 R16 — ADR-067 v2)」 — 표기는 출처일 뿐 내용은 **지금 규칙**이다.
- 「왜 이렇게 했나」의 이유 — 과거 사건을 인용해도 **현행 값의 근거**면 현행이다
  (예: 「720p·5초 실측 10~15MB 라 상한을 50MB 로」 → 상한 50MB 의 이유라 남긴다).
- 호출 구도·운영 시나리오·가드·권한·파라미터 목록 — 현행 규칙.
- 「구 모델(…)은 자동 경로에서 폐기됐으나 수동 경로로 존치」 — **존치**라는 현행 규칙을 담으면 현행(또는 혼합: 폐기 경위만 옮김).

## 본문 충돌 (옮기지 않는다)

예: 본문 「관제 측 주기 폴링 없음」 + 같은 문단 괄호 「⚠ 2026-08-03 정정 — '웹훅 기본 + 조회 보완' 으로 바뀌었다」.
경위를 빼면 「폴링 없음」이라는 **틀린 규칙**만 남는다. 이럴 땐 `본문 충돌` — 담당자가 본문을 현행으로 고친 뒤 옮긴다.
같은 항목의 다른 문단이 뒤집힌 경우도 본다(묶음에 같은 항목 문단이 함께 있다).

## 혼합의 조각 고르기

- 조각은 **원문에 글자 그대로** 있어야 한다(공백·기호·줄바꿈까지). 스크립트가 대조해 틀리면 거부한다.
- 문장 단위로 끊어라. 괄호 안 경위만 옮길 땐 괄호째(「(2026-08-28 개방 — 구 … 폐기)」).
- 조각을 빼고 남는 문장이 **문법적으로 서야** 한다. 서지 않으면 `현행` 으로 두라.
- 제목 줄(「### 규칙별 관측 현황 (2026-09-15 기준)」)은 그 아래 본문과 함께 판단한다.

## 입력·출력

- 입력: 묶음 파일 — `[{pid, item, type, title, field, text}]`. 같은 항목의 문단이 모여 있다.
- 출력: 판정 파일 — **모든 pid 에 대해** `[{"pid": "...", "kind": "...", "move": ["..."], "reason": "..."}]`
  (`현행` 은 `{"pid","kind":"현행"}` 만).
- JSON 은 Write 도구로 쓴다. 쓴 뒤 `python3 -c "import json;d=json.load(open('<파일>'));print(len(d))"` 로 개수가 입력과 같은지 확인하라.
- ☠️ `pkill`/`kill` 패턴·stdin 대기 명령(`cat > file`) 금지. DB·서버 접근 금지. 입력 파일 수정 금지.

## ☠️ 구현 기록(implementation_record) 은 분리 대상이 아니다
구현 기록의 notes 는 «무엇을 어떻게 구현·검증했나»를 적는 **기록 자체**다 — CO 번호·QA 판정·검사 수치·커밋이 곧 본문이다.
경위로 빼면 항목이 빈다. 전부 「현행」으로 둔다(MindLog 실측: 판정자 9명 중 1명만 이렇게 봤고, 나머지는 IMPREC notes 를 통째로 경위로 빼려 했다).
그중 **다시 찾아갈 위치(커밋·테스트 경로)** 는 Phase 3.6 이 `evidence` 칸으로 따로 옮긴다.
