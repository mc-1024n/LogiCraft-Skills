# 재료 E — 관계 초안 판정 (Phase 1.8)

## 무엇을 판정하나

`relation-cands` 가 만든 작업표의 행 하나 = **빈 연결 칸 하나**(예: `SCREEN-069.realizes_requirements`)와
그 칸에 들어갈 수 있는 **후보 항목 몇 개**다. 후보는 스크립트가 세 신호로 뽑았다.

| 신호 | 뜻 | 믿을 만한 정도 |
|---|---|---|
| 직접 언급(산문 밖 칸) · 상대가 이 항목을 언급 | 두 항목이 이미 서로를 가리킨다 | 높음 — 그래도 **방향·종류**는 확인 |
| 그래프 2홉(X 경유) | 이 항목과 연결된 X 가 후보와도 연결돼 있다 | 중간 — X 가 허브면 약하다(점수에 이미 반영) |
| 그래프 3홉 | 두 다리를 건넜다 | 낮음 — 대부분 우연 |
| 같은 도메인 | domain_id 가 같다 | 낮음 — 거의 보조 |
| 드문 낱말 겹침 | 프로젝트에서 드문 낱말을 둘 이상 공유 | 낮음 — 같은 말이 다른 뜻인 경우가 많다 |

☠️ **신호는 판정이 아니다.** 점수가 높아도 두 항목의 본문을 **직접 읽고** 정한다.
상용 Self 시험: 「ADR-025 경유 REQ-012」가 아티팩트·공지·렌더 수용기준 모두의 1순위 후보로 떴는데 전부 오답이었다
(ADR-025 가 REQ-012 를 한 번 언급했을 뿐).

## 판정 질문 하나

> **「후보 항목이 내일 바뀌면, 이 항목을 다시 열어 봐야 하나?」**

예면 **제안**. 아니면 **아님**. 두 항목을 다 읽어도 모르겠으면 **보류**.

칸마다 뜻이 다르다 — 작업표 `field_help` 를 먼저 읽어라:

| 칸 | 「예」인 경우 | 흔한 오답 |
|---|---|---|
| `based_on_adrs` | 이 항목이 그 결정의 **결과**다(결정이 바뀌면 이 항목의 모양이 바뀐다) | 같은 주제를 다룰 뿐인 결정 · 이 항목이 **원인**이 된 후속 결정(방향 반대) |
| `implements_requirements` · `realizes_requirements` | 이 항목이 그 요구를 **충족시키는 수단**이다 | 요구가 이 항목을 언급만 함 · 상위 요구의 형제 요구 |
| `operates_on` | 이 항목이 그 데이터 모델을 **실제로 읽거나 쓴다** | 이름만 비슷한 테이블 · 모든 쓰기가 남기는 감사 로그 |
| `actor_roles` · `required_roles` | 그 역할이 이 행위를 **한다 / 해야 한다** | 관리자라 뭐든 할 수 있다는 일반론 |
| `constrained_by_nfrs` | 그 NFR 의 수치가 바뀌면 이 항목의 구현이 바뀐다 | 전역 NFR(모든 것에 걸림) — 넣으면 소음 |

## 판정 JSON

```json
[{"key": "SCREEN-069|realizes_requirements", "target": "REQ-012",
  "verdict": "아님", "reason": "REQ-012 는 ERD DDL 생성 요구 — 아티팩트 갤러리와 무관. ADR-025 가 한 번 언급한 우연한 경로."},
 {"key": "AC-053|based_on_adrs", "target": "ADR-027",
  "verdict": "제안", "reason": "코드 seed 21종을 DB 로 옮긴다는 이 수용기준은 ADR-027 «프리셋 갤러리 DB 단일화» 결정을 검증한다."}]
```

- `reason` 은 **필수**(10자 이상) — 사람이 검토표에서 이 한두 문장만 보고 채택·기각을 정한다.
  「관련 있음」 같은 말은 쓸모없다. **무엇이 무엇에 기대는지**를 적는다.
- `target` 은 **실재하는 항목**이어야 한다 — 작업표 후보 밖이어도 되지만(`_(후보 목록 밖)_` 표시), 프로젝트에 없는 ID 는 전체 거부된다.
- 한 칸에 제안은 **많아야 2~3개** — **결정·요구·NFR 칸**(`based_on_adrs`·`implements_requirements`·`constrained_by_nfrs` 등)에서.
  다 관련 있어 보이면 가장 직접적인 것만 — 넓게 걸수록 재검토 표시가 번진다.
  **나열형 칸**(`consumes_apis`·`operates_on`·`triggers`·`consumes`)은 상한이 없다 — 주 흐름이 실제로 부르는·다루는 것은 **전부** 제안한다.
  대체 흐름에서만 쓰는 것은 보류로 둔다(상용 Self rel-2: 상한 때문에 주 흐름 API 6줄이 보류됐다가 담당자가 채택).
- 판정하다 **산문이 낡은 곳**(가리키는 결정·요구와 어긋난 서술)을 보면 보고에 한 줄씩 남긴다 — 관계 보강의 부수 효과다(rel-1·2 에서 10건).
- 후보 전부 아니면 전부 「아님」으로 적는다(장부에 남아 다음에 다시 판정하지 않는다).

## 왜 자동 적용이 없나

재료 A~D 는 근거가 **글자로 어딘가 적혀 있어서** 스크립트가 대조할 수 있다. 재료 E 는 대조할 글자가 없다 —
AI 의 판단이 곧 근거다. 그래서 적용 권한을 사람에게 둔다. 사람이 채택한 줄만 `담당자 확정:` 근거로 적용되고,
변경 요약에 「AI 가 제안한 관계를 담당자가 검토해 채택했다」가 남아 나중에 출처를 가릴 수 있다.
